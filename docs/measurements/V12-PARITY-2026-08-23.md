## Interpretation (first probe — superseded by root cause below)

- **Governor off is not sufficient** for reference parity. Service was `inactive`; `MPE_POLY_GOVERNOR=0` in `/etc/mpe/mpe.env`; `surge-poly-governor=inactive` at soak start.
- **Same ~33% as V12 512 arm** (governor on) and as 1024 arm minute 1 — load path is capped below reference, not a meter mismatch.
- **On-disk poly state** at probe time: `~/.patch_browser_poly_state.json` → `ceiling_poly: 12`, `effective_poly: 9`, `native_poly: 16` (touch UI service inactive).

### Root cause (2026-08-23 follow-up)

`load-patch-osc.py` runs via `sudo -u mitch` **without** `MPE_POLY_*` in the child env. `PatchLoader._apply_playback_policy` then:

- `governor_enabled_by_env()` defaults `MPE_POLY_GOVERNOR` to **on** when unset
- `poly_ceiling()` defaults to **12** when `MPE_POLY_CEILING` unset
- effective poly → **9** (`min(16,12) − headroom 3`)

Reference cells use `measure-latency-run.sh`, which calls `mpe_source_appliance_env` before hold — but the same `_run_cell` load-patch gap may apply; **P5 revalidation on Pi** still required after fix.

**Fix (repo):** `measure-soak-instrument.sh` — `mpe_source_appliance_env` after env write; governor-off sets `MPE_POLY_CEILING/FLOOR=64`; `_as_user` exports poly vars into load/MIDI children.
