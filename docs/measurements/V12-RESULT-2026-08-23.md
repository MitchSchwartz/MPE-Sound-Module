## Finding 1 — 512 arm is underloaded vs reference (not a meter mismatch)

**Instrument:** both V12 soak and reference suite use **`jack_cpu_load`** piped to `.log.dsp` / confirm harness — ruled out.

**Reference (A4 pass 1):** Cloud Horn @5, 512×2, governor **off**, Condition A → **58.17%** median (`reference-suite-pi4-a4-spread-2026-08-23.md`).

**V12 512 arm:** same patch and voice count, governor **on**, steady **~33.3%** for all 1803 samples (first minute through minute 30).

**Likely mechanism:** governor-on load path caps effective poly at **9 on load** (`min(native 16, ceiling 12) − headroom 3`), then recovers toward ceiling **12**. Reference runs with governor stopped and native **16**. Cloud Horn uses two oscillators × five held notes (~10 voices). Poly **9–12** vs **16** is enough to explain ~57% of reference CPU (~33/58) without invoking a different meter.

**Touch/UI state at run time:** `~/.patch_browser_poly_state.json` → `ceiling_poly: 12`, `effective_poly: 9`.

**Implication:** minute-1 O1b passed (33% > floor 12.5) but **does not prove reference-comparable load**. A rerun needs governor **off** (or explicit parity target, e.g. dsp within band of reference cell P5) before any 512×2 citation or §1 challenge.

## Finding 2 — 1024 arm cliff voids the comparison (not gradual thermal drift)

**Pattern:** `v12-b1024-p2.log.dsp` holds ~33% through ~sample 62, then drops to ~10% over ~15 samples (~15 s), then ~8–10% for the remaining ~29 minutes.

**Not explained by:**

- Governor limit drops — journal shows only startup `9 → 12 reason=recover`; no `step_down` / `high` / `spike` / `warm`.
- 512-arm MIDI overlap — 512 soak ended ~16:33; 512 `midi-load-hold` killed in cleanup; 1024 MIDI started 16:34:04.
- Surge/jack restart at cliff time — no `surge-xt-cli` / `mpe-jackd` entries 16:34:50–16:35:30.

**1024 arm startup mess (confound, not root cause of cliff):** header 16:33:08 but loaded hold began ~16:34:04 (double jack/surge cycle during `set-surge-audio` + soak restart). Minute-1 plausibility used cumulative DSP including warmup; **per-minute window would have failed at minute 2** (~10% median).

**Root cause of cliff:** **unresolved.** Load fell on Surge; MIDI hold was still scheduled for 1920 s. Next step: reproduce with per-minute plausibility enabled and capture Surge voice count / poly OSC / MIDI process liveness at minute boundaries.
